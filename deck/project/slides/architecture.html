What it buys

  • Personal data never leaves. It is a hard constraint evaluated before any cost or latency optimisation, and the gate fails closed — classifier down means cloud refused, not cloud unchecked.
  • Safety without an outage. Failing closed degrades to on-prem rather than returning an error.
  • One config line swaps a model. No release, no code change, and the compliance behaviour is unaffected by the swap.
  • Every decision is auditable: who answered, which zone, which guard fired, what it cost — refusals included.

What it still costs

  • Two controls overlapped and the cruder one silently vetoed the precise one — blocking 66% of customers who gave their name. Found by a load test, not by 133 unit tests.
  • The PII classifier is the ceiling at 2.9 requests a second, single process. Stateless, so it scales with replicas.
  • In-process tests never check the deployment. A stale gateway answered attacks for eight hours while every test passed.
  • An output-guard rejection has no retry path. The customer gets a 502. Known and unfixed.

This is the architecture slide, and I have put the limits next to the strengths on purpose. The pipeline across the top is the order things happen in. The important one is stage two and three. Personal data is a hard constraint, which means it filters the choice of provider before cost or latency get a vote. A preference can be outvoted; a constraint cannot. And the gate fails closed. If the classifier is down we cannot prove the request is safe to send outside, so we refuse cloud entirely and serve it on-prem. That is safety without an outage, which is the distinction that usually gets lost. On the right hand column — I would rather you hear these from me.

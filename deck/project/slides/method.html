Every step taken · and the same step at production grade

Five disciplines, each one gated by a number rather than an opinion.

Discipline What was done here What it measured At production grade
Evaluation 185-message dataset, 36 deliberately tricky. Three PII detectors scored against it, with a promotion gate. Composite F1 1.000. The gate blocked two of the three candidates: regex recall 0.676, Presidio 0.784, both under the 0.95 floor. Nightly evaluation in CI. The gate blocks promotion rather than reporting it. Dataset owned by a second author.
Security 1,000 hand-written attacks — 50 originals × 20 deterministic mutations — re-run after every change. 988 of 1,000 held. Five runs; run four went up, catching a regression I had introduced myself. Same harness as a pull-request gate. garak and PyRIT nightly on GPU, with this as the fast gate in front.
AI-enabled QE The local model invented 100 attacks. Output frozen for reproducibility, then curated before scoring. 50 of 100 were not attacks — ordinary customer language. Of the 50 that were, 49 held, and they exposed an attack class I had never written. Regenerate per release, freeze per release. Curation rules reviewed, because the curator is now a control.
Performance Three load scenarios separated: control plane alone, end to end, and the compliance path. Control plane ceiling 2.9 req/s — flat from 1 to 16 concurrent, which traced it to a dependency, not the gateway. k6 in CI with thresholds from this baseline. Classifier replicated: N replicas give N × 2.9 req/s.
Governance 23 scenarios in one source of truth, each bound to tests by marker and verified by parsing both files. 23 of 23 traced, 133 tests passing. The matrix is generated, so it cannot quietly go stale. Same, plus coverage gates and an admission policy that refuses to schedule PII workloads outside the on-prem zone.

Extrapolation assumes GPU inference nodes and horizontally replicated classifiers. Throughput is the only figure extrapolated, and it scales with replicas. No other number in this deck is projected.

This is the method slide. The left three columns are what exists and ran; the right column is what the same discipline looks like with a real budget. The line I want you to take from it is the third row. I asked a local model to invent attacks, and half of what it produced was not an attack at all — it was ordinary customer language like "how do I get a refund". The raw score said seventy of a hundred got through. Publishing that would have been wrong twice over: it inflates the failure count, and it implies the guards should be blocking real customers. So generated test data gets curated before it is scored, and the curation rules are written down so you can argue with a specific line instead of the headline. The fourth row matters for a different reason. Splitting the load test in three is what turned a throughput number into a diagnosis. If I had only measured end to end I would have reported that the governance layer does 0.28 requests a second, which would have been true and completely misleading.
